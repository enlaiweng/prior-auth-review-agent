# Golden Dataset Datasheet

EDOM Phase 3 artifact, kept with the golden set. Shape follows Gebru et al., Datasheets for Datasets. Updated whenever the set is repaired.

## Motivation

Created to evaluate a prior authorization review agent against Medicare LCD L34220 (Lumbar MRI) when no public prior authorization case data exists. Cases and notes written by Claude, an AI engineering agent, under Enlai Weng's review; answer key by Enlai Weng (Amendment 2). Patients generated and cases written 2026-10-15; the three held-out notes restyled by Enlai Weng in the Gemini app on 2026-10-15, Pacific time (the commit messages say 2026-10-16, the date in Claude's example instructions), with the model setting "Auto" on the free tier, so the exact Gemini model is not recorded. Each restyled note was then normalized for typography only (`eval/tools/normalize_note.py`) and checked fact by fact against the note before restyling; the one fact lost, the visit type "Follow-up" in notes 08 and 10, was put back in the note's own style, in a separate commit.

## Composition

Twelve cases (twenty in the original plan; reduced on 2026-10-13, before any case was authored). Each case is one FHIR R4 bundle (Patient, a Claim for the requested MRI, Conditions, Encounters, Observations, and one DocumentReference holding an authored clinical note, plus Procedures, MedicationRequests, and DiagnosticReports where the case has therapy, medication, or an imaging report) plus label files. By adjudicated outcome: 4 approvable, 3 documentation gap, 5 route. Within those twelve: 5 adversarial cases, of which 2 carry instruction-like text in the note; 3 held out from tuning (cases 08, 10, and 12, written and locked before any version of the agent existed, with notes restyled in another model's writing style). Cases are numbered 01 to 12. They first kept the original 20-case allocation's numbers (01 to 10, 12, 15); on 2026-10-18, before any label existed, case 15 was renamed case 11 at the owner's request so the numbers have no gaps (ARCHITECTURE.md, ADR-11). Its content did not change; its record ids changed from case15- to case11-. The encrypted intended answers still use the old name, and data/golden/intended_answers.md gives the mapping. Not counted in the twelve: two paired fairness duplicates (case 01 with the patient's sex changed, case 09 with race changed, otherwise identical, with the same resource ids and note), made by `eval/tools/make_pair.py` and stored beside their originals. Demographics come from Synthea; clinical episodes were authored to exercise specific criteria of L34220 (revision effective October 23, 2025).

## Labels and labeling protocol

Per-criterion status (supported, unsupported, undeterminable) for every L34220 criterion applicable to the case, the record element supporting each status, the expected routing, and, for gap cases, the named missing item. Protocol (Amendment 2; EVAL_PLAN.md, How the answer key is made): Claude's intended answers locked in an encrypted file committed on 2026-10-15 (pull request #4), key published on 2026-10-25 in `data/golden/intended_answers.md`, with the decrypted file committed as `intended_answers.yaml`; Enlai Weng's blind labels entered and submitted on the online labeling site on 2026-10-24 (Pacific) and committed on 2026-10-24 at 22:38 Pacific (pull request #12) in each case's `labels_blind.yaml`; the site's "Download submitted labels" file is kept unchanged in `data/golden/site_exports/`, the twelve files were made from it by `labeling-site/export_to_label_files.py`, a script run by Claude that copies the answers without judging them and first checks that each case he saw on the site is the case record in the repository, and the Checks workflow confirms on every pull request that each file is byte for byte what that export produces; the site shows the same case records as the labeling page (`eval/labeling/labeling.html`), which `eval/tools/build_case_pages.py` generates from the bundles together with each case's `case_page.md`, in the record's own words, adding only headings, short connecting words ("ordered", "status", "dosage period"), and the ids labels cite, and leaving out the patient's name, identifiers, address, race, and ethnicity, which no criterion uses; third reader gemini-3.8-flash through the Gemini API (the version Gemini reported for every case: gemini-3.8-flash; default temperature and thinking level), workflow run 40166566266 on 2026-10-24, 22:44 to 23:08 Pacific, all 12 cases labeled on the first attempt, given the prompts in `eval/third_reader/prompts/`, built from the same case pages by `eval/tools/build_third_reader_prompts.py` and committed before labeling with a fingerprint for each; disagreements settled by Enlai Weng against the policy text, with reasons, in each case's `labels.yaml`; tie-break: if still split after re-reading the policy, label undeterminable and route. A training written by Claude from the criteria and routing rules only (`eval/labeling/TRAINING.md`), with two practice cases outside the golden set and their worked answers (`data/practice/`, on `eval/labeling/training.html`), the first taught step by step in a guided walkthrough, was added before labeling; an independent reviewer checked the worked answers against the criteria and the practice cases for closeness to any golden case before it was merged (decision log, 2026-10-18). Enlai Weng worked through the training several times before labeling, on the training page and as a test labeler on the labeling site. Outside labelers, if any, labeled on the online labeling site (labeling-site/README.md; ARCHITECTURE.md, ADR-13): each from a personal link, credited by the name and role they entered after agreeing to be named and to label on their own, seeing only the cases assigned to them and no other reader's labels, with labels locked on submission and exported to the repository with who and when: none as of the reveal. While labeling, looking up what a single medical word means in a dictionary or on MedlinePlus was allowed; searching for how to label a case, and putting any case text into an AI tool, were not. The key was kept in the project's Claude workspace until the reveal; not using it early was an honor rule. Agreement before settling (`data/golden/disagreements.md`): Enlai with Gemini 8 of 12 at the routing level and 44 of 48 criterion statuses; Enlai with the intended answers 7 of 12 and 43 of 48; Gemini with the intended answers 11 of 12 and 47 of 48; nurse with final labels [x of n, or not done]. Enlai knew each case's designed outcome, so his labels are blind at the criterion level, not at the routing level; Gemini and the nurse did not know the design.

Policy reading for C1, adopted 2026-10-14 before any case was authored. L34220 lists "other nerve root compromise" among its red flags and describes "no red flags" as no symptoms or signs suggesting nerve root disorder or spinal cord dysfunction. Read that way, any radiating leg pain would count. The same text also describes red flags as findings that suggest a medically emergent condition, qualifies its neurologic items as "clinically significant or progressive," and says an MRI for uncomplicated disc herniation is not medically necessary unless surgery or another aggressive treatment is under consideration. Read that way, only objective deficits count. National imaging guidance takes the second view. The ACR Appropriateness Criteria for low back pain (2021 update) describe patients as having pain "with or without radiculopathy" and "no red flags," rate MRI as usually not appropriate at first, and rate it usually appropriate after six weeks of management in a candidate for surgery or an injection. The American College of Physicians and American Pain Society guideline (Chou and colleagues, 2007) reserves prompt imaging for severe or progressive neurologic deficits or a suspected serious condition, and MRI for radiculopathy to persistent symptoms in a candidate for surgery or an epidural steroid injection. Commercial utilization criteria reviewed (BlueCross BlueShield of South Carolina, MRI Lumbar Spine CAM 709; HealthHelp 2025 lumbar MRI guideline) also require objective deficits or about six weeks of failed conservative care for adults. These do not bind a Medicare Advantage plan applying L34220 and are cited only as practice. This dataset therefore labels C1 supported for objective nerve root or spinal cord compromise in the record (clinically significant or progressive weakness, a reduced or absent reflex, sensory loss in a nerve root pattern, new bladder or bowel dysfunction, saddle or perianal sensory loss) and C1 unsupported for radiating leg pain or a positive straight leg raise alone. Each case's expected routing is also worked out under the broader reading before the case is committed, and a case whose routing would differ is rewritten (EVAL_PLAN.md, Golden set composition). No Noridian guidance interpreting "other nerve root compromise" was found. A conversation with a utilization management reviewer would test this reading and is noted as open. C3 follows the eval plan's wording, which applies the LCD's condition that "a surgical intervention or other aggressive treatment" be under consideration to every case that does not rest on a red flag, not only to the LCD's named example of uncomplicated disc disease; the ACR and ACP guidance cited above likewise ties MRI for persistent low back pain to candidacy for surgery or an injection.

## Provenance and generation

Synthea master-branch-latest, build d9d07a6 (downloaded 2026-10-15), run on Java 21 (OpenJDK 21.0.12) with UTF-8 file names, seed 20260910, clinician seed 20260910, reference and end date 2026-08-15, population 100 living patients (157 generated in all), age filter 55 to 90, state California, US Core export on. Two runs gave byte-identical output. UTF-8 file names matter: without them, Synthea could not save patients whose names have accented letters, which would have dropped mostly Hispanic-named patients from the pool. Java versions can give slightly different patients from the same seeds, which is why the Java version is recorded. Twenty patients were drawn by `eval/tools/list_patients.py --pick 20` (the first living patients in file-name order that give the age mix, so the choice is fixed but not random), fifteen of them aged 65 or older (twelve are used in version 1.0; two of the rest are used by the practice cases in data/practice/, and the others are kept for a later expansion), because a Medicare Advantage membership is predominantly 65 and older with a minority enrolled under 65 on the basis of disability. From each Synthea record only the Patient resource and a thin allowlisted baseline (up to three stable chronic conditions and their medications, nothing touching the spine, malignancy, infection, fracture, opioids, or imaging) were kept, with US Core profile tags stripped so bundles validate against base R4; the low back pain episode, therapy history, imaging history, requested-procedure Claim, and note are authored on top. Baselines in `data/golden/baselines/`; each case (spec, note, bundle, case page, labels) in `data/golden/case_NN/`. Patients with diabetic kidney disease receive acetaminophen rather than anti-inflammatories, as a clinician would prescribe. Baselines also drop Synthea's disability- and quality-adjusted life year scores, which summarize the whole simulated history, including what the baseline leaves out. Validator: HL7 FHIR validator 7.0.2 (download fingerprint pinned in `.github/workflows/validate-golden-set.yml`), base R4, structure only (no terminology server; the renderer's codes were checked by hand), with Synthea's own extensions allowed and only the US Core race, ethnicity, and birth sex extension definitions loaded (`eval/fhir-defs`; no US Core profiles applied). It runs on GitHub's computers on every change to a case, loading the FHIR packages that validator version asks for from packages.fhir.org; zero errors required. The workflow's summary lists each case's result and its warnings, and the same workflow checks that every bundle, case page, and prompt is up to date with the spec and note it was made from. Run on a machine that cannot reach packages.fhir.org, with packages assembled by hand, the same validator reported a false error on the note's file type in three bundles; the results recorded here come from the official packages. Regeneration commands in `data/golden/README.md`.

## Uses

Intended: evaluating criterion-level reasoning, citation faithfulness, gap detection, and routing for lumbar MRI prior authorization under L34220. Not intended: any other policy or procedure; training; any inference about real populations.

## Known limitations

Synthetic records are cleaner and more internally consistent than real charts. Cases and notes were written by Claude, and the agent under test is a Claude model; nine of the twelve notes are in Claude's writing style, and the three held-out notes were restyled in another model's style to test this. The restyled notes are template-style, with capitalized headings and short phrases, so a reader can tell those three apart from the rest; that tells a reader which cases are held out, not how they should be labeled. The adjudicator knew each case's designed outcome. Two of the three readers are AI models; only the nurse check, if done, adds a qualified human who did not know the design. The set is small; a single case moves a percentage by about eight points.
